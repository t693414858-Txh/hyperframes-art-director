# Recurring account delivery

Read only for an authorized account-delivery or publishing task with an existing
project contract. Ordinary art direction and editing do not require this workflow.

## Resume the correct work

Read the project's workflow, publication contract, current authorization and
active delivery records. Resolve the episode and exact export from the latest
request and publication evidence, not file modification time alone. Keep one
active delivery pack and use existing records instead of creating a second ledger.

Distinguish these states: production, render verified, delivered, upload prepared,
awaiting authorization, publishing, published or blocked. A successful render,
file transfer or thumbnail does not establish publication. An already published
record prevents duplicate upload unless the user requests republication.

## Preserve the approved production

Keep the current topic, approved voice, visual direction, cost limits and selected
quality checks. Apply a requested aesthetic skill before making the artwork and
recording it. Do not substitute unrelated click recordings or static slides for
promised real operation.

Prepare the exact final video, title, full description, relevant tags, cover and
any promised comment resource. Use the project's pack format. Verify disclosure,
privacy and claims against the actual final file.

## Handoff and publication

Resolve the user's current authorization, including any scoped standing grant,
before external actions. A style or render approval is not publication permission.
Preserve authorization boundaries and any required action-time confirmation;
recording a workflow does not grant new permissions or create a schedule.

Use the project's maintained device, account and platform instructions. Keep
coordinates, platform limits, input-method workarounds and device recovery there,
not in this shared Skill. Inspect fresh UI state after a failure; preserve the
draft and report a concrete blocker rather than repeatedly re-uploading.

Before the final action, verify the account, exact selected file, complete fields,
cover, visibility and required disclosure. Record one publication attempt. If
the result is uncertain, inspect the work list or detail before any retry.

## Close with evidence

Record the actual file/version, published wording, time, visible status and any
uncertainty in the existing publication record; reconcile the active pack and
ledger. Do not infer success from navigation or a tool response alone.

Retain the project's authorized follow-up and notification rules. This Skill
does not create recurring jobs or authorize replies to incoming messages.
Post-publication analysis should use the actual measurement window and work
identity, not a duplicate upload or predicted retention score.
