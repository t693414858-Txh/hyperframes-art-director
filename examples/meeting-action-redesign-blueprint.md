# Meeting Discussion to Accountable Action

This blueprint redesigns a generic light editorial meeting video around a project-specific mechanism. The light palette may remain, but report pages, presenter placement, and captions are supporting elements rather than identity.

## Recognition Target

Without the title, Codex label, presenter, captions, or call to action, the sequence should still read as:

`Noisy meeting language is converted into tasks with owner, deadline, and acceptance criteria, then verified as executable.`

## Recurring Mechanism

Use one four-field action contract:

| Field | Initial state | Final state |
| --- | --- | --- |
| Task | Ambiguous sentence | Atomic deliverable |
| Owner | Missing or collective | One accountable person |
| Deadline | Relative or absent | Exact date and time |
| Acceptance criteria | Missing | Observable completion standard |

The visual state progresses through:

`unresolved -> specified -> verified`

## Scene Blueprint

### Scene 1: Information Noise

- Show real or faithfully derived conversation fragments, not a report dashboard.
- Empty owner, deadline, and acceptance slots remain visibly unresolved.
- Core identity: yes
- Proof: source transcript or message capture
- Swap test: another project requires different source evidence, field model, and composition

### Scene 2: Codex Extraction

- Show the real prompt or interface operation that extracts the first action contract.
- Conversation fragments physically resolve into the four fields.
- Core identity: yes
- Proof: real Codex input and output
- Swap test: another product requires different interface evidence, semantic mapping, and motion

### Scene 3: Gap Audit

- Keep missing owner, deadline, and acceptance fields visibly open.
- Use error states only where the source evidence is incomplete.
- Core identity: yes
- Proof: extracted action with unresolved fields
- Swap test: changing labels is insufficient because the gap logic and data structure are specific

### Scene 4: Repair and Verification

- Show the follow-up evidence that fills each missing field.
- Transition each field from unresolved to specified to verified.
- Core identity: yes
- Proof: source reply, updated output, or verification state
- Swap test: another project requires new evidence, field transitions, and timing

### Scene 5: Executable Contract

- Resolve on one compact action contract rather than a generic report page.
- Preserve task, owner, deadline, and acceptance criteria at readable scale.
- The presenter may support the frame but cannot cover or replace the contract.
- Core identity: yes
- Proof: final verified output
- Swap test: another project requires a different final artifact and verification mechanism

## Remove or Reduce

- Persistent chapter-navigation shell
- Generic summary cards
- Decorative colored panels without evidence meaning
- Presenter occupying the same corner in every frame
- Keyword-led final frame disconnected from the demonstrated mechanism

## Keep

- Light neutral canvas
- High legibility
- Restrained motion
- One semantic status-color system
- Calm instructional pacing
